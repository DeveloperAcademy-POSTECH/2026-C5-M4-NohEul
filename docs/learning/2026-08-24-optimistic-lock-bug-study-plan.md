# 오늘의 학습 계획 (120분, 단일 사이클)

## GQ/GA 목록

| | 내용 |
|---|---|
| GQ1 | 현재 프로젝트에서 낙관적 락 코드의 버그는 무엇일까? 해결 방법은? |
| GQ2 | 스프링에서 낙관적 락은 어떻게 동작할까? |
| GQ3 (제안) | 이 버그는 왜 지금까지 발견되지 않았을까? (테스트 커버리지 부재인가, 동시성 재현 자체가 어려워서인가) |
| GA1 | 현재 코드 구현 확인 + 버그 재현하기 |
| GA2 | 공식문서 기반으로 MySQL·Spring이 낙관적 락을 어떻게 처리하는지 공부 |
| GA3 (제안) | 학습한 내용 바탕으로 실제 수정 코드 작성 → GA1에서 재현한 시나리오로 재검증 |
| GA4 (제안) | 동시 요청을 재현하는 테스트 케이스로 버그를 재현 가능한 형태로 고정 → Notion 버그리포트/테스트케이스 DB에 기록 |

## 시간 배분

| 시간 | 활동 | 목표 |
|---|---|---|
| 0~15분 | GA1 착수 — 낙관적 락 관련 코드(엔티티의 @Version 필드, 서비스 레이어의 save/update 로직) 전체 훑기 | 지금 코드가 뭘 하고 있는지 파악 |
| 15~40분 | GA1 계속 — 버그 재현 시도. 흔한 낙관적 락 버그 패턴부터 의심해보기 | 버그의 정체를 특정 |
| 40~80분 | GA2 — 공식문서 학습: Spring Data JPA @Version 동작 방식, MySQL 자체엔 낙관적 락이 없고 애플리케이션/ORM 레이어에서 조건부 UPDATE로 구현된다는 원리 확인 | GQ2에 답 + GQ1의 원인 가설 세우기 |
| 80~105분 | GA3 — 학습한 원리로 실제 수정 코드 작성, GA1에서 재현한 시나리오로 검증 | GQ1에 답 |
| 105~120분 | GA4 요약 — 오늘 확인한 버그·수정·재현 테스트를 Notion에 기록, 다음에 볼 GQ 하나 남겨두기 | 학습 정리 + 재발 방지 기록화 |

GA1에서 확인해볼 흔한 낙관적 락 버그 패턴:
- @Version 필드가 응답 DTO에서 누락돼 클라이언트가 옛날 버전으로 재요청하는 경우
- 조회(SELECT)와 수정(UPDATE)이 서로 다른 트랜잭션에 걸쳐 있어 버전 체크가 무력화되는 경우
- 벌크 업데이트(@Modifying 쿼리)가 버전 컬럼을 무시하고 직접 UPDATE 치는 경우
- OptimisticLockException 발생 시 재시도 로직이 없어서 그냥 요청이 실패로 끝나버리는 경우

## GA별 AI(Claude)의 역할

| 활동 | 무엇을 하나 | AI(Claude)의 역할 |
|---|---|---|
| GA1 — 코드 확인 + 버그 재현 | 낙관적 락 관련 코드 훑고 버그 재현 시도 | - 코드를 같이 읽으며 놓치기 쉬운 지점(트랜잭션 경계, @Version 필드 흐름 등)을 질문으로 짚어주기<br>- "이 부분에서 조회와 수정이 같은 트랜잭션 안에 있는지 확인해봤어?" 식으로 유도<br>- 동시 요청을 어떻게 재현할지 아이디어(멀티스레드 테스트, Postman 동시 요청 등) 제안 |
| GA2 — 공식문서 학습 | Spring/MySQL 낙관적 락 원리 학습 | - 공식문서(Hibernate @Version 문서, Spring Data JPA 레퍼런스) 링크 찾아주기<br>- 이해가 안 되는 개념을 사용자가 먼저 설명하게 하고, 정확한지 검증(잘못 이해한 부분만 짚어줌)<br>- 헷갈리는 지점을 비유로 설명 |
| GQ3 — 왜 안 잡혔나 | 재발 방지 관점 성찰 | - 테스트 커버리지 관점에서 체크할 질문 목록 제시<br>- 정답 대신 "이 QA 관점에서 뭐가 빠졌을까?"라고 되묻기 |
| GA3 — 수정 코드 작성 + 재검증 | 학습 내용 바탕으로 실제 수정 | - 사용자가 먼저 짜고, AI는 리뷰·피드백만(직접 대신 짜주지 않음)<br>- 놓친 엣지케이스를 지적<br>- 재현 테스트로 실제 고쳐졌는지 같이 검증 |
| GA4 — 테스트케이스 작성 + 문서화 | Notion에 버그리포트·테스트케이스 기록 | - 테스트케이스/버그리포트 템플릿 구조 제안<br>- 사용자가 쓴 문서 초안을 리뷰해서 빠진 정보 짚어주기 |

공통 원칙: GA1~GA3은 AI가 먼저 답을 주면 학습 효과가 떨어지는 구간이라 막혔을 때만 힌트 요청. GA2·GA4는 AI가 정보 탐색·구조화를 적극적으로 도와도 학습을 방해하지 않는 구간.
